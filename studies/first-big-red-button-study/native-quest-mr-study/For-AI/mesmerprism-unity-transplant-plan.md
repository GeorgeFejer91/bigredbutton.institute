Implemented in native branch `first-study-native-mesmerprism-transplant`:

The active path uses the idle GLB plus 32 `models/glow/BigRedButtonGlowLevelXX.glb` variants generated by `tools/create-button-glow-variants.py`, based on the Unity cap tint/emission behavior from `BigRedButtonBlinkController.cs` and tonemapped to a hot red/orange native peak so the Meta Spatial renderer does not wash the cap to white. The native pulse envelope now mirrors Unity's 320 ms ease-in/out pulse and 250 ms refractory. Small cap-surface point lights and subtle metal-bezel warmth assist the effect while the dark base material remains preserved. The flat 2D panel glow remains in code only as a disabled fallback.
- ECG diagnostics/export: native app now writes pulse metadata on ECG blink rows, threshold R-peak detector diagnostics in `*_ecg_detector_events.csv`, and an empty disabled-by-default external-signal CSV for future LSL/broker inputs.
- LSL: only the schema/logging scaffold is present. No `liblsl.so`, JNI wrapper, network discovery, or threshold trigger is active yet.

Still not completed by this transplant:

The current build therefore swaps precomputed GLB material variants instead of mutating the embedded GLB material directly.
- Press-motion retiming against a final reviewed button-press sound. The app still triggers the GLB `pressed` clip and logs the future alignment hook.
- Final human/H10 evidence: live Polar PMD ECG and human controller-contact/full-export validation still require headset operator runs.

## Unity Systems Worth Porting

### Button Press Dynamics

Relevant Unity files:

- `Assets/Scripts/BigRedButtonManualPressController.cs`
- `Assets/Scripts/BigRedButtonPressInteractor.cs`
- `Assets/Scripts/BigRedButtonGeneratedBodyCollider.cs`
- `Assets/Scripts/BigRedButtonPressColliderProxy.cs`
- `Assets/Editor/BigRedButtonSceneInstaller.cs`
- `Assets/Editor/QuestVrSceneInstaller.cs`

Findings:

- Unity does not rely on a single broad invisible box. It generates mesh-derived colliders from the GLB renderers, fits a press trigger surface to the cap/top band, and compares interactor colliders against the cap mesh/surface.
- The press surface is tuned through model-local overrides in the Unity GLB:
  - `TriggerSurfaceStableLocalPosition = (-0.000021076481, 0.017285282, 0.0044704)`
  - `TriggerSurfaceStableLocalEuler = (328.31277, 180.4872, 359.38284)`
  - `TriggerSurfaceStableLocalSize = (0.006696218, 0.0012468889, 0.006696218)`
  - `TriggerColliderStableDerivedLocalOffset = (0, -0.0027, 0.0016)`
- Do not paste those constants directly into the native app. They are local to the Unity 221 KB GLB, while the native app currently uses a different 88 KB GLB.
- Unity uses startup suppression and cooldown values close to the native app:
  - startup suppression: `0.35 s`
  - press cooldown: `0.18 s`
- Unity keeps an active-interactor latch so continuous overlap does not generate repeated presses until the interactor leaves and re-enters.
- Unity's interactor model is body based: it builds/generated colliders from hand/controller renderers and disables legacy hand physics capsules to avoid noisy duplicate hits.

Native transplant steps:

1. Keep the current native GLB unless a deliberate visual/kinematic asset swap is chosen and revalidated.
2. Add a build-time or validation-time GLB geometry profile for `app/src/main/assets/models/BigRedButton.glb`:
   - identify cap node/mesh `button` / `button_cap`;
   - compute cap top center, radius/diameter, thickness, and approximate surface normal;
   - emit constants or a JSON profile consumed by validation and possibly runtime.
3. Replace or supplement the single `IsdkBoxCollider` with a cap-matched press target:
   - preferred: SDK-supported sphere/capsule/cylinder/mesh collider if available;
   - fallback: 5-9 small box colliders arranged as a circular cap approximation, rather than one large box.
4. Add a per-source/interactor latch mirroring Unity's `_activeInteractorIds`, so held contact does not repeatedly count presses after cooldown.
5. Preserve `controller_contact` as the final physical proof source; keep `hand_contact` as separate supplemental provenance.
6. Add static checks that the contact target remains centered on the visual cap and remains within the existing ergonomic layout contract.

### Press Motion

The two known GLBs are not byte-identical:

- Unity/MesmerPrism local GLB: SHA-256 `5B0E13AC4854C8E508BA7EAD8807E7D655EDB169F88FE39A16AFD2BCD4EE8887`, size `221924`, nodes `RootNode`, `button`, `joint1`, `stand1`.
- Native study GLB: SHA-256 `4BA2C479EAE6A103ADCE0B7D0AB70C94A5F21A12435DD90ACD0071F66EF5F52B`, size `88132`, nodes `RootNode`, `button`, `cap_side_shadow`, `metal_bezel`, `button_base`.

Both have an animation named `pressed`, but:

- Unity animates `joint1.translation`, 24 keyframes, duration about `0.958333 s`, local displacement about `3.29 mm` in Y and `2.06 mm` in Z.
- Native animates `button.translation`, 3 keyframes, duration about `0.16 s`, local Y dip about `3.8 mm`.

Native transplant steps:

1. Treat Unity's longer clip as a motion reference, not an automatic replacement.
2. For near-term feel, add a configurable native press-motion curve that can reproduce Unity's diagonal/local easing while still triggering the GLB `pressed` animation for compatibility.
3. When the final button sound is chosen, retime the cap displacement to the sound envelope as described in `docs/button-press-sound-and-motion.md`; do not change the two instruction MP3 durations.
4. Log press motion start, estimated max-depression time, release time, and sound trigger time if sound-motion alignment becomes a dependent validation target.

### Heartbeat / RR Glow

Relevant Unity files:

- `Assets/Scripts/BigRedButtonBlinkController.cs`
- `Assets/Scripts/Biofeedback/PolarHeartbeatButtonDriver.cs`
- `Assets/Scripts/TheBigRedButtonInstitute/IndirectParticles/Biofeedback/Heartbeat/PEPolarHeartbeatModule.cs`
- `PEHeartbeatPulseShaper.cs`
- `PEHeartbeatPulseSynth.cs`
- `PEHeartbeatPeakDetector.cs`
- `PolarHeartRateTransportRouter.cs`

Findings:

- Unity drives the button from Polar HR/RR events more than from direct ECG R-peak detection.
- RR notifications are routed to a raw signal registry with `polar_hr_rr_ms` and `polar_hr_rr_beat_count`.
- The heartbeat module turns beat-count deltas into pulse events with:
  - baseline pulse around `0.10`;
  - peak `1.0`;
  - decay around `0.25 s`;
  - stale timeout around `2.0 s`;
  - minimum beat interval around `0.25 s`.
- The Unity glow is material/surface based: it copies a runtime material, interpolates tint/emission, enables emission, and optionally drives 1-4 point lights positioned on the cap surface.

Native transplant steps:

1. Keep the native BLE/PMD implementation as the primary Polar path; it is already Android-native and records high-resolution PMD ECG windows.
2. Port Unity's heartbeat pulse shaping semantics into a small native `HeartbeatPulseDriver`:
   - source: `real_polar_h10` RR initially, then PMD ECG-derived R peaks once a detector is validated;
   - stale timeout: `2 s`;
   - refractory/min interval: `250 ms`;
   - baseline/peak/decay matching Unity defaults.
3. Replace the current visual-only warm overlay with the most model-attached glow the Meta Spatial SDK allows:
   - preferred: runtime material/emission update on the cap material;
   - fallback: duplicate translucent cap/glow shells or small surface glow entities centered on the cap, never a flat 2D halo.
4. Keep all existing `EcgBlinkEvent` JSON/CSV fields and add optional `pulseIntensity`, `pulseSourceTimestamp`, and `detector` fields only with schema-validation updates.
5. For real ECG-derived R peaks, add a separately validated detector over `PolarEcgSample.microVolts` instead of replacing the RR path immediately.

### LSL / External Signal Routing

Relevant Unity files:

- `Assets/Scripts/Diagnostics/BigRedButtonDirectLslDriveReceiver.cs`
- `Assets/Plugins/Android/arm64-v8a/liblsl.so`
- `Assets/Scripts/RustyXrBroker/RustyXrBrokerButtonDriver.cs`
- `Assets/Scripts/RustyXrBroker/RustyXrBrokerBioSignalReceiver.cs`
- `Assets/Scripts/RustyXrBroker/RustyXrBrokerProtocol.cs`

Findings:

- Unity has a direct LSL inlet worker that resolves by stream name/type, opens `liblsl`, pulls float samples in a background thread, maps a chosen channel to `0..1`, and triggers on a threshold/rising edge with a minimum interval.
- Unity defaults include stream name `HRV_Biofeedback`, type `HRV`, channel index `0`, trigger threshold `0.5`, and minimum interval `0.25 s`.
- Unity also has a broker protocol for streams such as `bio:polar_hr_rr`, `bio:polar_ecg`, and `bio:polar_acc`; it normalizes stream samples and records diagnostics.
- The native app currently has no LSL subsystem.

Native transplant steps:

1. Treat LSL as a new optional diagnostic/signal-input subsystem, not as a replacement for native Polar capture.
2. Package `liblsl.so` under `app/src/main/jniLibs/arm64-v8a/` only after confirming Android compatibility on Quest.
3. Add a small JNI wrapper or native Android-compatible binding for:
   - resolve by property;
   - create/open inlet;
   - pull float sample;
   - close/destroy inlet.
4. Add Android network/multicast support only if LSL discovery requires it on the Quest network path; document any extra manifest permission and runtime lock.
5. Route accepted LSL samples into the existing condition logger as external signal rows and optional blink-drive events. Do not count LSL threshold pulses as participant button presses unless the protocol explicitly adds that condition.
6. Add loopback validation:
   - local desktop LSL outlet simulator;
   - Quest log marker for connect/sample/threshold;
   - exported LSL CSV rows with source stream metadata.

## New-Agent Integration Brief Delta - 2026-06-12

Source brief inspected: `https://github.com/MesmerPrism/the-big-red-button-institute/blob/codex/brb-questionnaire-panel-bridge/Documentation/New-Agent-Integration-Brief.md`.

The Unity project is still a parallel implementation, not an engine dependency for this native app. Use it as a behavioral and integration reference only: button feel, signal routing, diagnostic boundaries, and validation habits can transfer, but Unity scene/components and Unity-specific Android bridge code should not be imported into this Meta Spatial SDK/Kotlin app.

Questionnaire-panel bridge lesson:

- The Unity branch now demonstrates a clean Android product boundary for a standalone questionnaire panel: explicit intent, `request_json`, caller-owned `content://` result URI, write-only URI grant, one-shot immutable broadcast `PendingIntent`, and caller-side result validation by `request_id`/`nonce`.
- The current native app keeps questionnaires in-process, so it does not need this caller/callee IPC path. Still, the same contract shape is useful internally: explicit stage names, versioned request/result schema, validation-only auto-submit flags, durable pending state before panel display, and no answer data in logs, filenames, public shared storage, or callback extras.
- Do not replace native questionnaire validation with ADB relaunches, public storage exchange, overlays, package killing, `file://`, `QUERY_ALL_PACKAGES`, or `SYSTEM_ALERT_WINDOW`. ADB remains a development/validation launcher only.

Brokerless signal-route lesson:

- Unity now documents direct Polar, direct LSL, and direct OSC-style routing without requiring the Rusty XR broker. This supports the native app's current direction: native Polar PMD ECG/RR remains primary and broker-independent, while any future external signal route should be optional and separately validated.
- Unity's direct Polar route blinks the button from heartbeat samples through a blink-only runtime entry point. The native app already has the stronger study path: real Polar PMD ECG/RR is recorded in both conditions, feedback source is counterbalanced, and heartbeat flashes go through `HeartbeatPulseDriver` plus GLB material variants.
- Unity's direct LSL route defaults to `HRV_Biofeedback` / `HRV`, channel `0`, threshold `0.5`, rising-edge pulse, and minimum interval `0.25 s`. The native app currently has only a disabled external/LSL CSV scaffold and logs `BRB_LSL status=disabled`; if LSL is activated later, decide deliberately whether to adopt Unity-compatible stream defaults or document a different native contract.
- LSL threshold pulses must not satisfy the final participant press requirement unless the study protocol is explicitly changed. In this native study, final proof remains human Quest controller contact with the 3D button plus live Polar H10 PMD ECG coverage.

Validation takeaway:

- Keep validation-only shortcuts obvious and logged. Unity's questionnaire `debugAutoSubmit` maps conceptually to native hidden/qkv validation shortcuts, but participant runs must use real foreground interaction and final controller-contact pressing.
- If the standalone questionnaire-panel pattern is ever adopted by the native app, add tests for URI grant scope, callback-after-stream-close ordering, duplicate callback idempotency, process-death recovery, package visibility, and privacy leakage, mirroring the `quest-questionnaire-panel` validation matrix.
